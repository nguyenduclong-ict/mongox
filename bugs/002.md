# Bug Report 002: Restore Namespace Remapping, Export Database URI Conflicts, and Sidebar Refresh Actions

## 1. Investigation & Root Cause Analysis

### Issue 1: Database Restore into a new database name succeeds but the database does not appear
- **Observed Behavior**: The user selected a dump archive file (e.g. created from `test_db`), entered a new database name (e.g. `test_123`), and executed Restore. The process completed with success toast, but `test_123` was not found.
- **Root Cause**:
  1. `mongorestore` preserves namespaces embedded inside the BSON archive metadata (e.g., `test_db.customers`). When `--nsInclude=test_123.*` was supplied without namespace remapping, `mongorestore` filtered out all collections originating from `test_db`, restoring 0 collections and 0 documents while exiting with status code 0 (success).
  2. To restore collections from a source archive into a differently-named target database, `mongorestore` requires `--nsFrom="<source_db>.*"` and `--nsTo="<target_db>.*"`.
  3. The frontend `handleRunRestore` also needed to await `reloadHierarchy()` so that newly restored database namespaces immediately reflect in the sidebar hierarchy.
- **Resolution**:
  - Implemented `detect_archive_database` in `BackupService` with deep inspection of the BSON header key `\x02db\x00` and `is_gzip_file` detection based on magic bytes `[0x1F, 0x8B]`.
  - In `build_restore_arguments`: when `target_db != source_db`, generate `--nsFrom="<source_db>.*"` and `--nsTo="<target_db>.*"`.
  - Updated `useConnection.ts` to make `reloadHierarchy` async returning a `Promise<DatabaseInfo[]>` and `await reloadHierarchy()` in `App.tsx`.

---

### Issue 2: mongoexport failure: Cannot specify different database in connection URI and command-line option
- **Observed Behavior**: `mongoexport failed: error parsing command line options: Invalid Options: Cannot specify different database in connection URI and command-line option ("test_db" was specified in the URI and "admin" was specified in the --db option)`.
- **Root Cause**: The connection URI string stored with the profile contained a path component with the database name (e.g. `mongodb://.../test_db?authSource=admin`). When exporting from a different database (e.g. `--db=admin`), `mongoexport` detected a conflicting database between the URI path and the `--db` CLI flag and aborted execution.
- **Resolution**:
  - Added URI path database stripping via `BackupService::strip_database_from_uri(uri)`.
  - Applied `strip_database_from_uri` in `build_export_arguments` and `build_import_arguments` in `ExportImportService` as well as `build_dump_arguments` and `build_restore_arguments` in `BackupService`.

---

### Issue 3: Refresh buttons in action menus for Connections, Databases, and Collections
- **Requirement**: Add a Refresh action button into the context/action menu for connections, databases, and collections in the Sidebar views.
- **Resolution**:
  - Added `Refresh` (`RefreshCw` icon) item to:
    1. Connection right-click context menu and hover action.
    2. Database right-click context menu and hover action.
    3. Collection right-click context menu and hover action.
  - Linked actions in `App.tsx` (`handleRefreshConnection`, `handleRefreshDatabase`, `handleRefreshCollection`), triggering `reloadHierarchy()` and workspace data cache refresh key.
